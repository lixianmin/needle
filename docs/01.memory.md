# 项目记忆

## 关键决策

- **2026-10-22 传输用 SSE，不用 WebSocket。** WebSocket 在 Node 要 `ws`、在 Bun 要 `serve()` 时传 `websocket`、在 Workers 必须有 Durable Object 并改 wrangler 配置；SSE 只要一个 `(Request) => Response`，三处零接线。Workers 的 HTTP 请求没有 wall time 上限，够用。
- **2026-10-22 包名 `@needle/logo`。** `logo` 与 `logo-ts` 在 npm 上都已被占用。
- **2026-10-22 控制台拆 kernel + 适配器。** `createConsoleSource()` 是纯逻辑，HTTP/SSE、浏览器 DOM 是它的两个适配器；否则同一套命令要写两遍。
- **2026-10-22 日志是缓冲批量的。** sink 收的是 batch；`warn`/`error` 立即写出且把积压一起带出去，达到上限强制 flush 而不是丢弃。
- **2026-10-22 指标检测不做 import。** workerd 不接受非字面量的 `import()`，只能用能力探测（`typeof process?.memoryUsage`）。
- **2026-10-22 前端用 Solarized Dark。** 配色表在 spec §11，不自己调色。
- **2026-10-22 落盘格式 `时间 [I] JSON`。** 东八区、秒级；time/level 只在前缀，不进 JSON；`formatLine` 统一 stdout/文件/控制台三处。
- **2026-10-22 日志命令叫 `log.list`。** 跟 gonsole 同名；列的是磁盘日志文件，点文件名用 header 鉴权取回全文（不带 URL token）。
- **2026-10-22 `core/logo/` 只放日志，sink 集中在 `core/logo/sinks/`。** file sink 依赖 `node:fs`，只从 `./node` 导出；`. ` 入口不拉它（miniflare 测试断言产物无 `node:`）。collections 只收泛型结构；环形的 ring sink 已删（无使用方）。
- **2026-10-22 `dist/` 提交进仓库。** Git 依赖不能要求消费者构建；`.githooks/pre-commit` 每次提交跑 `bun run build` 并 stage `dist/` + `script.generated.ts`，克隆后需 `git config core.hooksPath .githooks`。
- **2026-10-22 版本号每次合进 main +1 patch。** 规则在 `AGENTS.md` §14；minor/major 人类定；`examples/demo.ts` 从 `package.json` 读版本。
- **2026-10-22 不提供 `logout`。** 登录态靠 token `exp` 自然过期（默认 12h，`auth.ttlMs` 可调），没有主动退出命令。
- **2026-10-22 不提供框架适配入口。** 没有 `./hono` 之类 subpath，`hono` 也不进 dependencies/devDependencies。对外只有 `(Request) => Response` 的 handler：Fetch 形态（Hono/Workers/React Router 资源路由）直接接；Node 形态用 `./node` 的 `attach(server, debug, { basePath })`，它接管 `request` 事件、前缀外交回原 listener。不做自动嗅探 mount。钉在 `test/unit/no-hono-coupling.test.ts`。
- **2026-10-22 路由是表驱动的，用 `:name` 而非框架。** `src/console/router.ts`：`{ method, pattern, handler }`，`/log/<name>` 即 `/log/:name`，参数只吃一段；剥 `basePath`、尾斜杠不算命中都在那里。不引三方路由库（会破 no-hono 测试）。spec §8.2 是与实现对齐的路由表。
- **2026-10-22 错误响应统一走 `ResponseX`（`src/core/web/responsex.ts`）。** 失败一律非 2xx + `{code, message}`，成功响应不加壳（`ok` 只在内部 ExecResult）。8 个方法锁死状态码+code，调用方只给 message；一个状态码一个 code，细分靠 message。内部 `ExecFailureCode` 保持 6 种原因，`exec.ts` 用 switch 映射。契约表见 spec §8.2。
- **2026-10-22 JSON 响应直接用内置 `Response.json`。** 不再手写 `new Response(JSON.stringify(...))`；`exec.ts` 保留 3 行 `reply()` 承载 `Body` 联合类型的编译期约束。响应头随运行时（Node/workerd `application/json`、Bun 带 charset），JSON 只能是 UTF-8，无需自定 charset。
- **2026-10-22 测试里的版本号用 `test/fixtures.ts` 的 `TEST_VERSION`。** 测试断言的是透传，值无关，固定常量比读 `package.json` 好（改版本号不该弄红测试）；`node smoke` 跑 dist，读 `package.json` 真值。

## 经验教训

- **运行时能力探测不要用动态 import。** workerd 要求静态模块说明符，`import(变量)` 会在部署/运行时报 `ERR_MODULE_DYNAMIC_SPEC`。改用 `typeof` 能力探测；这类问题只有真跑 workerd（miniflare）才会暴露，Bun/Node 上测不出来。
