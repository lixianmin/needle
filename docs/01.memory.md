# 项目记忆

## 关键决策

- **2026-10-24 SSE 心跳 2 秒、无条件发。** 链路上最短的「无数据即断开」超时是应用服务器自己：`Bun.serve()` 的 HTTP `idleTimeout` 默认 10 秒（实测 10 秒掐连接、客户端 `ECONNRESET`）；原来的 15 秒 + 「空闲才发」让面板每 10 秒断一次、刷「连接失败」。心跳只存在于 Shell 的 `/events`，每个面板一个定时器，8 字节/2 秒可忽略。spec：`2026-10-22-logo-design.md` §8.2。

- **2026-10-24 日志面板按落盘格式渲染（`formatPayload`）。** 原来只渲染 `msg`，而请求日志是纯对象参数（不产生 `msg`），面板里只剩时间戳。现在级别 + `文件:行 [fn()]` + 紧凑 JSON 全上，栈例外（行下单独铺开）。面板与文件共用 `formatPayload`，`formatLine` = 时间 + 它。

- **2026-10-24 相对导入统一带 `.js`，目录导入写 `index.js`。** 包是 `nodenext`（tsc 不改写说明符，Node ESM 也不解析无扩展名/目录），所以 `import "./x.js"` 是硬要求；示例原本是 `bundler` 解析、写无扩展名，统一成 `.js` 只为「同一仓库一种写法」，顺带把 `"./api"` 这类目录导入显式写成 `"./api/index.js"`。

- **2026-10-24 变异测试用 Stryker，必须 `--inPlace`。** TS 7 没有 `ts.parseConfigFileTextToJson`，Stryker 沙盒的 tsconfig 预处理直接崩；`--inPlace` 跳过沙盒。测试必须 import `../src/*`（走包名测的是 dist，变异源码打不到测试，config.ts 曾因此 0 分）。当前 82.33%，阈值 break 80，`bun run mutate` 约 1.8 分钟。

- **2026-10-24 示例的接口文件精简到 2 个（health / bots）。** 一个领域一个文件、同文件挂多条路由（GET + POST），不再一个接口一个文件——文件数量不是覆盖度。`bots.ts` 里同时演示：query 取单条/全表、批量 POST + 部分缺失、`import { viper }` 取配置。

- **2026-10-24 配置与日志不进 request context。** `HonoxEnv` 只留每请求独有的 `uid` / `user` / `authError` / `rid` / `api`。要配置就 `import { viper }`，要日志就 `import { logo }`，不再有 `c.set("config")` / `c.set("log")` 与 `HonoxEnv<C>` 泛型。

- **2026-10-24 请求日志去掉箭头；结束行位置指向 API 文件。** 两行分别由字段区分：进 `{rid, path}`、出 `{rid, path, status, durationMs, uid}`。位置靠 `createApi()` / `apiRoute()` 在注册时抓 `文件:行` 存 context（handler 不在栈上，callerDepth 指不到）。示例里一个领域一个组：`export const botsApi = createApi()` 然后 `botsApi.get(...)` / `.post(...)`，每条路由各自记自己的注册行。logo 加 `callerDepth`（对应 Go 的 `SetFuncCallDepth`）与 `captureCallSite()`；调用方显式传的 `site`/`fn` 优先于自动抓的。

- **2026-10-24 honox 的中间件链独立成 `src/middleware.ts`。** `installMiddleware(app, {config, log, auth, public})` 依次装 rid → 请求日志 → JWT → 门禁，顺序由库固定；`index.ts` 只做装配（建实例、算白名单、挂 Shell）。`createRequestLog` 也住这个文件，改名不再需要改两处。

- **2026-10-24 各包构建开 `declarationMap`。** dist 提交在仓库里，`types` 指到 `dist/*.d.ts`；没有 declaration map 时编辑器「跳转到定义」只能停在 .d.ts（甚至 JS）。开了之后 IDE 顺着 map 跳到 `src/*.ts`。代价：`.d.ts` 尾部多一行 sourceMappingURL，dist 里多 56 个 `.map`（也要提交，否则构建后 git 变脏）。
- **2026-10-24 日志行带调用点，格式照 Go 版 logo。** `日期T时间 [I] 文件:行 [fn()] {json}`；`site`/`fn` 只在前缀，不进 JSON。每级都抓（一条日志一次 `new Error`，代价明码），完整栈仍只给 `stackLevel`（默认 error）。请求日志直接用传入的 logger，不 `child`；`method` 字段删了（路径已能定位）。判读日志仍用 `parseLine`（找第一个 `{`，前缀里 `[I]`/`[fn()]` 都有 `]`）。

- **2026-10-24 请求 id 叫 rid，用 Snowflake 生成，入站有就沿用；对外一律字符串。** 读 `x-rid`，其次 `x-request-id`；都没有才生成。id = 63 位（41 毫秒 + 10 机器号 + 12 序列），**编码成定长 13 位小写 Crockford Base32 返回**：63 位装不进 JS number（2^53），而 `JSON.stringify(bigint)` 直接抛——靠每个调用点记得 `.toString()` 迟早会忘，所以从生成那刻就是字符串，写日志/进 JSON/存 Mongo-MySQL 都不用转。定长是为了「字典序 = 数值序」：变长十进制会让新 id 排到旧 id 前面，B 树回头插就是页分裂。按原版 Snowflake 处理时钟回拨（直接拒绝）。

- **2026-10-24 配置改成 viper 风格取值器，ENV 只认 dev/fat/pro。** `loadConfig` 返回 `Config`：`getString/getInt/getBool/getStringMap/get/has/raw` + `isDev/isFat/isPro`。`ENV` 是唯一由 loadConfig 读的环境变量，业务侧不再碰 `process.env`；其它覆盖走 `APP_*` 点分路径。取值缺省且无 fallback 即抛（比 viper 零值严）。示例的 Shell 账号来自 `server.shell_users`，镜像 `ENV=pro` + `app_pro.yml` 不写 auth.secret → 必须传 `APP_AUTH__SECRET`。

- **2026-10-24 示例的 HTTP 接口放 `app/api/`，一个接口一个文件，参数走 query。** `app/api/index.ts` 只做 `registerApis(app)` 登记，`app/main.ts` 不写路由；每个文件 `new Hono<AppEnv>()`，`AppEnv` 来自 `app/env.ts`。`GET /apc?id=` 取单条、不带 id 取全表（id 是筛选条件，不做路径段）。uid 与请求日志由 createHonox 的中间件链自动提供，接口里不用手写。

- **2026-10-24 新增 `@needle/honox`：唯一允许依赖 hono 的包。** core/logo/shell 仍不依赖任何框架；no-hono 测试收窄为「honox 例外 + 源码扫描白名单（packages/honox、examples/honox-app）」。`createHonox()` 返回 Hono 实例，业务若用 HonoX 则 `createApp({ app })` 接入（spike 验证：父层中间件先跑、`c.get("uid")` 在文件路由里可读）。鉴权默认拒绝 + 白名单。spec：`docs/superpowers/specs/2026-10-24-honox-design.md`。

- **2026-10-24 honox 的元数据照 rim.server：扫目录 + sheet 名后缀分派。** 启动 `metadata.load(dir)` 扫 `res/metadata`：`*Template` 按 id 建表（第一层 key 是 sheet 名），`*Config` 取首个非空行当全局单例，其它跳过。代码里不写文件名、不写清单——新增表只加 `app/md/` 一个文件。manager 是显式实例（不是模块级全局），测试各建一个不串状态。`id` 只允许数字，缺 id / 非数字 / 重复 / 同名 sheet 跨文件都在 load 时报错并带 `文件#sheet` 与行号。hucre 只能异步读，所以必须启动预载、getter 同步。拆列靠「类即 schema」：模板写成 class，字段默认值 `equips: string[] = []` 即声明该列按 `|` 拆（元素 trim、保留 `"0"`、空单元格 `[]`），逐列换分隔符用 `static separators = { tags: "," }`；业务侧不写 `split("|")`。sheet 名取类名（`metadata.template(ApcTemplate)`），**构建不能开 `--minify`**（类名会被抹平，那时要显式补名字）。

- **2026-10-24 honox 示例不用 npm 的 `honox`（HonoX），TS 与根同版本。** 两者只是同名：示例把路由直接挂 `createHonox()` 返回的实例，`bun build` 打包，`export default { port, fetch }` 由 Bun 自己 serve。教训：HonoX 的岛检测（precinct → @typescript-eslint/typescript-estree）在 TS 7 上抛 `TypeError ... reading 'Cjs'`，带它就钉死 TS 5.9.3。示例仍不进 workspace（自带 tsconfig/lockfile），`@needle/*` 用 `link:`（`file:` 会让 `workspace:*` 解析失败）；`no-hono-coupling` 测试钉住「示例无 honox 依赖与 import、TS 与根同版本」。

- **2026-10-23 浏览器日志落 IndexedDB：`createIndexedDbStore()` 一个对象双身份（Sink + LogFiles）。** 手动接线：`logo.addSink(store)` 写、`logFiles: store` 读（BrowserShellOptions 零签名变更）；无 `log.export`，导出 = `log.list` 点开手动保存，与服务端同交互；tips 列表自带 sample（GONSOLE 同款，textContent 渲染防 XSS，服务端共用）；按级别级联出 info/warn/error 三个虚拟文件；保留 7 天 + 5000 条（时间轴锚设备时钟 + 入库 id 轴时钟无关）；库结构 v2 用 out-of-line 自增键（见教训）；一批一个 readwrite 事务，绝不逐条开事务。一切 sink 手动挂（服务端不自动挂 file sink）。Chrome 扩展 SW / 页面共享 origin 同一份 IDB（官方文档）；content script 的 IDB 属宿主页，不代写。spec：docs/superpowers/specs/2026-10-23-browser-log-store-design.md。

- **2026-10-22 传输用 SSE，不用 WebSocket。** WebSocket 在 Node 要 `ws`、在 Bun 要 `serve()` 时传 `websocket`、在 Workers 必须有 Durable Object 并改 wrangler 配置；SSE 只要一个 `(Request) => Response`，三处零接线。Workers 的 HTTP 请求没有 wall time 上限，够用。
- **2026-10-25 `core` 包改名 `got`：`@needle/got`（目录 `packages/got`）。** 只是改名：包内容（`SortedTable` / `Comparer` / `defaultComparer`）、入口（只有 `.`）、依赖方向（不依赖任何包）都不变；构建脚本 `build:core` 同步改成 `build:got`。改名理由未落盘（人类只给了指令），后续若有人问「为什么叫 got」，先问人类。
- **2026-10-24 拆成 `@needle/got` / `@needle/logo` / `@needle/shell` 三个 workspace 包，无伞包。** 两个目的：模块拆小，让人和 AI 读码、写码、review 时边界直接可见、单次上下文变小；边界由包解析与构建顺序硬约束（shell → logo，got 不依赖任何包），反向引用直接构建失败，从机制上杜绝循环引用。got 只留 SortedTable；原 `core/web` 内迁 shell；Node 能力按包出 `logo/node`、`shell/node`；构建顺序 got → logo → ui → shell；三份 dist 各自提交。版本号根单源：根 `package.json` 的 `version` 是唯一真值，`bun run version:sync` 写进三包（`package.json` 不支持引用），pre-commit 自动同步，`test/version-lock.test.ts` 钉住三包与根相等。spec：`docs/superpowers/specs/2026-10-24-three-packages-design.md`。
- **2026-10-22 Shell 拆 kernel + 适配器。** `createShellSource()` 是纯逻辑，HTTP/SSE、浏览器 DOM 是它的两个适配器；否则同一套命令要写两遍。
- **2026-10-22 日志是缓冲批量的。** sink 收的是 batch；`warn`/`error` 立即写出且把积压一起带出去，达到上限强制 flush 而不是丢弃。
- **2026-10-22 指标检测不做 import。** workerd 不接受非字面量的 `import()`，只能用能力探测（`typeof process?.memoryUsage`）。
- **2026-10-22 前端用 Solarized Dark。** 配色表在 spec §11，不自己调色。
- **2026-10-22 落盘格式 `时间 [I] JSON`。** 东八区、秒级；time/level 只在前缀，不进 JSON；`formatLine` 统一 stdout 与文件两处（右栏日志行单独渲染）。
- **2026-10-22 日志命令叫 `log.list`。** 跟 gonsole 同名；列的是磁盘日志文件，点文件名用 header 鉴权取回全文（不带 URL token）。
- **2026-10-24 目录：`packages/{got,logo,shell}/src`；测试跟包走（`packages/*/test`）。** 入口：got `.`；logo `.` + `./node`（file sink / log-files）；shell `.` + `./node`（serve / attach）；web 工具在 `packages/shell/src/web`。根 `test/` 只留 `smoke` 与 `build-fresh`。dist 三份各自提交，pre-commit 重建并 stage。
- **2026-10-22 `dist/` 提交进仓库。** Git 依赖不能要求消费者构建；`.githooks/pre-commit` 每次提交跑 `bun run build` 并 stage `dist/` + `script.generated.ts`，克隆后需 `git config core.hooksPath .githooks`。
- **2026-10-22 版本号每次合进 main +1 patch。** 规则在 `AGENTS.md` §14；minor/major 人类定；`examples/demo.ts` 从 `package.json` 读版本。
- **2026-10-22 不提供 `logout`。** 登录态靠 token `exp` 自然过期（默认 12h，`auth.ttlMs` 可调），没有主动退出命令。
- **2026-10-22 不提供框架适配入口。** 没有 `./hono` 之类 subpath，`hono` 也不进 dependencies/devDependencies。对外只有 `(Request) => Response` 的 handler：Fetch 形态（Hono/Workers/React Router 资源路由）直接接；Node 形态用 `@needle/shell/node` 的 `attach(server, shell, { basePath })`，它接管 `request` 事件、前缀外交回原 listener。不做自动嗅探 mount。钉在 `packages/shell/test/no-hono-coupling.test.ts`。
- **2026-10-22 路由是表驱动的，用 `:name` 而非框架。** `packages/shell/src/router.ts`：`{ method, pattern, handler }`，`/log/<name>` 即 `/log/:name`，参数只吃一段；剥 `basePath`、尾斜杠不算命中都在那里。不引三方路由库（会破 no-hono 测试）。spec §8.2 是与实现对齐的路由表。
- **2026-10-22 错误响应统一走 `ResponseX`（`packages/shell/src/web/responsex.ts`）。** 失败一律非 2xx + `{code, message}`，成功响应不加壳（`ok` 只在内部 ExecResult）。8 个具名方法锁死状态码+code（调用方只给 message），外加 `fail(status, code, message)` 逃生口；一个状态码一个 code，细分靠 message。内部 `ExecFailureCode` 保持 6 种原因，`exec.ts` 用 switch 映射。契约表见 spec §8.2。
- **2026-10-25 `ResponseX` 从 `@needle/shell` 入口公开导出。** 宿主应用（自己接路由的服务）复用同一套错误契约，不用另拼 `{code, message}`；导出后形状即契约，改这里等于改所有使用方。
- **2026-10-22 JSON 响应直接用内置 `Response.json`。** 不再手写 `new Response(JSON.stringify(...))`；响应头随运行时（Node/workerd `application/json`、Bun 带 charset），JSON 只能是 UTF-8，无需自定 charset。
- **2026-10-22 测试里的版本号用 `packages/shell/test/fixtures.ts` 的 `TEST_VERSION`。** 测试断言的是透传，值无关，固定常量比读 `package.json` 好（改版本号不该弄红测试）；`node smoke` 跑 dist，读 `package.json` 真值。
- **2026-10-23 包没发布到 npm。** `npm view @needle/logo` 返回 404，安装文档写 `bun link` 三个包；发布后改成 `bun add @needle/logo @needle/shell`。
- **2026-10-23 未登录只放 `auth` / `help`。** `Command.public` 删除；`help` 按身份过滤；未登录时 UI 只补全这两条、`sub`/`unsub` 被门禁。日志帧在多连接下只序列化一次（`Connection.sendText`）。
- **2026-10-23 一轮全量 review 修的坑。** SSE 断开不 cancel body（订阅者/定时器泄漏）、chunked 绕过 body 上限、metrics 永久缓存、fetch-adapter 中止级联重连、共享引用误判为循环、飞书丢 message/stack。
- **2026-10-23 文档按环境分篇，只写平台特有内容。** README 讲共用部分（Shell 、命令、日志、安装）；`docs/best-practices/` 三篇只写平台差异（挂载方式、鉴权开关、文件 sink、CSP 等），与 README 重复的一律删掉。服务端（Node / Workers）合在一篇 `node-server.md`，不再单开 `docs/deploy/`。
- **2026-10-23 README 只做入门，行为细则归代码注释 + spec。** 日志节原有 12 条「常见坑」，实测是代码注释（`packages/logo/src/logo.ts` 的 JSDoc、`record.ts`、`line.ts`）与 spec §6 的散文复述，已删；README 只留示例、攒批一句话、安装与平台边界。API 契约写在代码里（方法头 + options 字段），README 不复述。spec 与实现冲突以代码为准（§6.2 纯对象/数组、§6.4 时区措辞已按实现改）。
- **2026-10-23 破坏性改名走 minor：版本 0.3.0。** `createShell` → `createServerShell` 是删掉旧名的 breaking 变更，按 §14 由人类定：0.2.39 → 0.3.0（不自动递增 minor，改为人工拍板）。
- **批量改文案别用会吃掉换行的正则。** `s/([\p{P}])\s+Shell/g` 这类替换里 `\s` 含换行，把「标题」与下一段之间的空行一起吞了，node-server.md 的 H1 就与正文粘成一行。修法：批量替换后 diff 一遍，专门查被删掉的空行（`git diff` 里找孤零零的 `-`），正则优先用 `[ \t]+` 而不是 `\s+`。
- **框架路由的结论要实测，别照着直觉写。** 文档曾写「两条路由缺一不可」，实测：Hono 的 `/shell/*` 连基路径 `/shell` 也命中（一条就够），Express 4.22 的通配不匹配基路径（`/shell` 404，要补精确路由）。改法：凡是「框架 X 的路由语义」这类结论，先在 /tmp 里装一版真框架跑一遍再写进文档。
- **2026-10-23 产品名统一叫 Shell。** 代码里已是 shell / createServerShell / createBrowserShell，文档里原来的「控制台」、`CONSOLE_PASSWORD` / `CONSOLE_SECRET`、`console.html` 全部改成 Shell 口径：中文正文写「Shell」，环境变量 `SHELL_PASSWORD` / `SHELL_SECRET`，扩展页 `shell.html`。保留两处：「面板」指 DOM 那块 UI；JS 的 `console.*` 与「DevTools console」说的是浏览器控制台，不是本产品。

## 经验教训

- **Hono 中间件里 `await next()` 对 Error 抛出不会抛。** compose 每层把 Error 交给 `onError`、设好 `context.error` 后正常返回；但非 Error 抛出、`onError` 自己抛错、自定义 `notFound` 抛错仍会穿过来。所以两路都要收：`c.error` + `catch`，且 `finally` 里用 `c.finalized ? c.res.status : 500`——没 finalize 的 `c.res` 会惰性造一个 200，把失败记成成功。

- **IndexedDB 的 keyPath 不能借用业务字段名。** `keyPath: "id"` 会让记录里的业务 `id` 直接变成主键：同 id 的两条日志互相覆盖（静默丢日志），`id: null` 还会让 `put` 同步抛 `DataError`、连带整批后半截丢失。修法：out-of-line 自增键（不传 keyPath）；结构变了要升 DB 版本、在 upgrade 里重建 store。测试用「同 id 两条都要在」+「id: null 不中断整批」钉住。
- **sink 的 close 不能吞掉 flush 已入队的批次。** `logger.dispose()` 是「先 flush（此时 sink 入队）再 close」；sink 若在出队时再查 closed，最后一批静默丢失——恰好是 pagehide 场景最需要的那批。修法：closed 只在入队时刻判一次，关连接排到队列末尾。
- **数据库连接必须挂 onversionchange 让路**，否则别的上下文升级会无限期 blocked；而 blocked 不能判成永久失败——对方让路后 onsuccess 仍会到来，那时要撤销 failed 接管连接，否则 store 永久降级。
- **测试写完要反证：把修复摘掉必须变红。** 本轮出现过两个摆设测试：一个 close() 与 open() 同轮导致 blocked 根本没触发，一个固定 sleep 掩盖了竞态。修法：先观测到目标事件再继续，固定 sleep 换轮询。
- **IndexedDB 事务内 count 排在 delete 之后，已包含删除效果，别再手工扣减。** prune 曾把 expiredKeys.length 再减一次，过期+超限同批时条数超上限（少删不丢数据，reviewer 抓出）。修法：直接用 count()。测试这类混合场景要专门覆盖——单轴各自有测试时，交叉路径恰恰没人钉。
- **fake-indexeddb 测试注入 now 方向别反**：now 要注入到记录之后一天（cutoff 落在记录之前），注入晚于 keepDays 会让每批写完即被过期清理清空，症状像「读路径坏了」，实际是清理按设计工作。
- **运行时能力探测不要用动态 import。** workerd 要求静态模块说明符，`import(变量)` 会在部署/运行时报 `ERR_MODULE_DYNAMIC_SPEC`。改用 `typeof` 能力探测；这类问题只有真跑 workerd（miniflare）才会暴露，Bun/Node 上测不出来。
- **写进代码注释的契约一样会烂。** `LoggerOptions.stackLevel` 的 JSDoc 写着「默认 warn」，实现是 `error`（`packages/logo/src/logo.ts`），两边对着干了很久没人发现；README 同一时期写的一直是对的。改法：改默认值的同一个提交里改 JSDoc，评审时对着实现读一遍 options 注释。
- **对外 API 命名先想对称。** `createShell` / `createBrowserShell` 一个带限定词一个不带，读的人得先猜哪个是服务端。定名按「跑在哪」成对来：`createServerShell` / `createBrowserShell`，类型同样成对（`ServerShell*` / `BrowserShell*`）。

- **不 await 的 `expect(p).rejects` 是摆设。** `serve` 的「close 后端口不可连」用它，断言从未执行；改成重新 `listen` 同一端口（EADDRINUSE 才失败）既真正生效，也不会被并发测试复用的 ephemeral 端口拖到超时。
