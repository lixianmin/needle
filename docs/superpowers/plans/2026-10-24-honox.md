# @needle/honox 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 needle 仓库新增 `@needle/honox`——一个业务无关的 Hono 底座（配置 / JWT 鉴权 / 每请求日志 / 可选 Mongo / Excel 配置 / Shell 面板），外加一个可构建、可打镜像的 HonoX 示例 app。

**Architecture:** 包按运行环境拆四个入口（`.` / `./node` / `./mongo` / `./excel`），根入口不碰 `node:`；`createHonox(options)` 返回装配好的 `Hono`，中间件顺序（reqId → 日志 → JWT → 门禁）由库固定，鉴权默认拒绝、公开接口走白名单。示例 app 用 HonoX 的 `createApp({ app })` 把文件路由挂到同一个实例上，库本身不依赖 honox。

**Tech Stack:** TypeScript 7（仓库本体）、hono 4.13（peer）、honox 0.1.62 + vite（仅示例，TS 5.9）、`yaml`、`hucre`、`mongodb`（可选 peer）、bun:test。

**Spec:** `docs/superpowers/specs/2026-10-24-honox-design.md`

## Global Constraints

- 控制流一律带花括号，语句体独占多行；`else` 跟在 `}` 后面（AGENTS.md 代码风格）。
- 根入口 `@needle/honox` 的源码与打包产物不得出现 `node:` / `require(` / `import(`。
- 依赖方向：`honox → shell → logo`；`core` 不依赖任何包；整个仓库只有 `packages/honox` 与 `examples/honox-app` 可以出现 `hono`。
- 包版本不手改：根 `package.json` 是唯一来源，`bun run version:sync` 同步。
- 所有 401 走 `@needle/shell` 的 `ResponseX.unauthorized(message)`，响应体固定 `{code: "unauthorized", message}`。
- 注释写「为什么」，不写「是什么」；提交信息用 `feat:` / `test:` / `docs:` 前缀。
- 测试框架只用 `bun:test`；不引入 jest / vitest。
- 根 VERIFY（合并门禁）：`bun install && bun run build && bunx tsc --noEmit && bun test && node test/smoke/node.mjs`。

## Review Focus

1. 白名单路径匹配的边界：`/health?x=1` 的 query 串、`/assets` 与 `/assets/*` 的关系、`/users/:id` 是否吃掉多段、`/users/9/` 的尾斜杠。
2. JWT payload 的异常形状：`sub` 是数字 / 缺失 / 为 null，`claim` 指向嵌套对象，token 是 `Bearer` 之外的前缀。
3. 配置合并的边界：YAML 里同名字段是对象或数组却被 env 覆盖、值 `"0"` / `"false"` / 空串、`required` 指向不存在的父路径。
4. Excel 坏数据：缺 `id`、重复 `id`、整行为空、表头大小写、文件缺失。
5. 请求日志的完整性：404 未命中路由、handler 抛错、门禁短路三种情况下，`<--` 行都要在且 status / uid 正确。
6. Shell 挂在子路径时：`/shell`、`/shell/`、`/shell/log/x` 三条无 token 都应放行，而不是只放行最后一条。

- [ ] **Step 3: 实现**

`src/config.ts`（纯逻辑，无 `node:`）：

```ts
export interface EnvLike {
  readonly [key: string]: string | undefined;
}

/** "true"/"false" → boolean，纯数字串 → number，其余原样。 */
export function coerceValue(raw: string): unknown;

/** 对象递归合并、数组整体替换（与 rim.proxy 的 _deepMerge 同语义），返回新对象。 */
export function deepMerge(base: Record<string, unknown>, override: Record<string, unknown>): Record<string, unknown>;

/** 按 envPrefix + `__` 分隔的路径覆盖 base 的深拷贝。 */
export function applyEnv(base: Record<string, unknown>, env: EnvLike, prefix: string): Record<string, unknown>;

/** 逐条检查点分路径；缺失或空字符串抛错，消息里带全部缺失路径。 */
export function assertRequired(config: Record<string, unknown>, required: readonly string[]): void;
```

实现要点：`deepMerge` 返回新对象，不改正参数；`applyEnv` 先 `deepMerge(base, {})` 拷贝，再按 `APP_AUTH__SECRET` → `auth.secret` 写入（中间层不存在就建对象），值走 `coerceValue`。

`src/node.ts`：

```ts
import { readFileSync } from "node:fs";
import { join, resolve } from "node:path";
import { parse } from "yaml";
import { applyEnv, assertRequired, deepMerge, type EnvLike } from "./config.js";

export interface LoadConfigOptions {
  /** 配置目录，默认 "config"（相对 process.cwd()） */
  dir?: string;
  /** 环境名，默认 process.env.ENV ?? "dev" */
  env?: string;
  /** 环境变量源，默认 process.env */
  envVars?: EnvLike;
  /** 默认 "APP_" */
  envPrefix?: string;
  /** 必填的点分路径 */
  required?: readonly string[];
}

export function loadConfig<C extends Record<string, unknown>>(options: LoadConfigOptions = {}): C;
```

实现要点：

- 目录：`resolve(process.cwd(), options.dir ?? "config")`；环境名：`(options.env ?? process.env.ENV ?? "dev").toLowerCase()`。
- `common.yml`：`try { readFileSync } catch (err) { if (ENOENT) 视为 {} else throw }`。
- `app_<env>.yml`：读不到就 `throw new Error(\`找不到环境配置：${abs}（ENV=${env}）\`)`。
- 每个文件解析后必须是纯对象；`parse` 对空文件返回 `undefined`，当 `{}`。
- 合并链：`deepMerge(common, envFile)` → `applyEnv(merged, options.envVars ?? process.env, options.envPrefix ?? "APP_")` → `assertRequired(...)`。

`package.json` 加 `"yaml": "^2.9.1"` 到 `dependencies`，并加 `"./node": { "types": "./dist/node.d.ts", "default": "./dist/node.js" }`。

- [ ] **Step 3: 实现** `src/mongo.ts`

```ts
import { MongoClient, type ClientSession, type Db } from "mongodb";

export interface MongoOptions {
  uri: string;
  /** 不传就用连接串里的库名（driver 默认行为）。 */
  db?: string;
  /** 复用已有连接池；传了就不关它。 */
  client?: MongoClient;
}

export interface Mongo {
  readonly client: MongoClient;
  db(): Db;
  withTransaction<T>(fn: (session: ClientSession) => Promise<T>): Promise<T>;
  close(): Promise<void>;
}

export function createMongo(options: MongoOptions): Mongo;
```

实现要点：`const client = options.client ?? new MongoClient(options.uri)`；`db()` 返回 `options.db === undefined ? client.db() : client.db(options.db)`；`withTransaction` 用 `client.withSession((s) => s.withTransaction(() => fn(s)))`；`close()` 内部一个 `closed` 标志，只有自建的 client 才 `await client.close()`。不显式 `connect()`。

```ts
import type { MiddlewareHandler } from "hono";
import type { AuthErrorReason, HonoxEnv, PublicEntry } from "./types.js";

export interface AuthOptions {
  /** HS256 密钥 */
  secret: string;
  /** uid 取自哪个 claim，默认 "sub" */
  claim?: string;
  /** 默认 "authorization" */
  header?: string;
  /** 可选：从哪个 cookie 兜底取 token */
  cookie?: string;
  /** 白名单；空 = 全部要登录 */
```

- `matchesPublic` 用 `path.split("?")[0]` 比较；模式拆段，`:x` 匹配一段非空，末尾 `*` 表示前缀匹配且**基路径本身也算命中**（`/assets/*` 命中 `/assets`）；对象条目的 `method` 与请求方法都转大写比较。
- 取 token：`header` 名可配（默认小写 `authorization`），值按 `/^bearer\s+(.+)$/i` 取；取不到再试 `getCookie(c, cookie)`。
- `verify(token, secret, "HS256")`；`catch (err)`：`err instanceof JwtTokenExpired` → `"expired"`，其余 `"invalid"`（`JwtTokenExpired` 从 `hono/utils/jwt/types` 导入）。
- `uid`：`typeof payload[claim] === "string" && payload[claim] !== ""` 才认，否则按 `"invalid"` 处理（`user` 仍设为 payload）。
- 门禁：`matchesPublic(...)` 放行；否则 `c.get("uid") === null` → `ResponseX.unauthorized(message)`，message 按原因：`"需要登录"` / `"登录已过期"` / `"token 无效"` / `"token 缺少 uid"`。

```ts
  readonly name: string;

  all(): readonly T[];

export function defineSheet<T extends Record<string, unknown>>(options: SheetOptions): Sheet<T>;

/** 批量预载：逐个调 load()，遇到第一个错就抛。 */
export async function loadSheets(sheets: readonly Sheet<unknown>[]): Promise<void>;
```

实现要点：

- **没有全局注册表**：`defineSheet` 只返回句柄，不往模块级数组里塞。
- `load()`：`readXlsxObjects(readFileSync(fileAbs), { sheet: name, headerRow: 0, skipEmptyRows: true, transformHeader: (h) => h.trim().toLowerCase() })`；`readFileSync` 的 ENOENT 直接冒出去（消息含绝对路径）。
- 逐行校验：`id` 键缺失 / `typeof value !== "number"` / `Number.isFinite` 不成立 → 抛 `` `${fileAbs}#${name} 第 ${rowIndex + 2} 行 id 不是数字：${String(value)}` ``（+2 = 表头占 1 行 + 数组 0 基 → Excel 1 基）。
- 重复 id → 抛 `` `${fileAbs}#${name} 重复 id：${id}` ``。
- 构建 `Map<number, T>` 与 `readonly T[]` 到局部变量，全部成功后才替换实例状态（原子）。
- `get()` 未加载 → 抛 `` `Excel 尚未加载：先 await loadSheets(...)` ``。
- 文件按绝对路径缓存解析结果（同文件多 sheet 只读一次）；缓存放模块级 `Map<string, Promise<...>>`，加载失败时从缓存里删掉，允许重试。

`package.json` 加 `"hucre": "^1.2.0"` 到 `dependencies`，加 `"./excel": { "types": "./dist/excel.d.ts", "default": "./dist/excel.js" }`。
