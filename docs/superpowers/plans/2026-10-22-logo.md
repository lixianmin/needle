# logo 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建 `@noodle/logo`——一个零运行时依赖的 TypeScript 日志库，附带一个可在浏览器里敲命令、看日志、订指标的嵌入式调试控制台，同一份代码在 Node 与 Cloudflare Workers 上运行。

**Architecture:** 四个 subpath 入口（`.`、`./console`、`./node`、`./lark`）。核心只用跨运行时 API；日志记录是不可变的普通对象，通过同步 sink 函数扇出；控制台是一个 `(Request) => Response` 的 handler，服务端推送走 SSE，命令请求/响应走 POST。

**Tech Stack:** TypeScript 7.0.2（native tsc）、Bun 1.4（开发与单元测试）、Node 20+（生产）、miniflare（Workers 集成测试）。零运行时依赖。

**Spec:** `docs/superpowers/specs/2026-10-22-logo-design.md`

## Global Constraints

- 运行时依赖为空。devDependency 只允许：`typescript@7.0.2`、`@types/bun`、`miniflare`。
- `src/core/`、`src/console/`、`src/lark/` 里不得出现静态 `import ... from "node:*"`；`src/node/` 可以静态 import `node:fs`（这个入口本来就只有 Node 会用）。
- 包名 `@noodle/logo`，`"type": "module"`，`"sideEffects": false`。
- tsconfig：`strict: true`、`module: "nodenext"`、`target: "es2022"`、`declaration: true`。相对 import 一律写 `.js` 后缀。
- 日志级别 `debug | info | warn | error`，数值权重 `10 | 20 | 30 | 40`。
- 记录字段固定为 `time`（epoch 毫秒）、`level`、`name?`、`msg?`，其余是业务字段。`time`/`level`/`msg` 与业务字段冲突时保留信封值。
- 单文件 ≤ 150 行，单函数 ≤ 50 行。命名用完整单词。
- 每个任务提交前跑 `bun test` 与 `bunx tsc --noEmit`，两者都绿。
- 开发必须在仓外 worktree（`../noodle-<branch>`）内进行，提交只在 worktree 内，不 merge、不 push。

## Review Focus

这些是 spec 隐含、但任何单个任务的主线测试都不会自动覆盖的失败模式。逐条在拥有它的任务里落测试。

1. 日志参数里出现循环引用、BigInt、Proxy、带 getter 的对象时，`info()` 不能抛，也不能输出 `[object Object]`。
2. 写入速度超过环形缓冲容量时，进程不崩，`read()` 返回最近的 N 条且顺序正确。
3. 浏览器断开 SSE 后，该连接的定时器必须被清理——否则内存泄漏、进程无法退出。
4. `Authorization` 上是垃圾字符串、过期 token、别人的 token 时，返回 401 而不是 500。
5. `/exec` 收到非 JSON、超大 body、超长命令时，返回明确错误码且连接不挂起。

### Task 2: Logger 门面与 sink 扇出

**Files:**
- Create: `src/core/logger.ts`、`src/core/ring.ts`、`src/core/runtime.ts`、`src/core/index.ts`
- Test: `test/unit/logger.test.ts`、`test/unit/ring.test.ts`

**Interfaces:**
- Consumes: `buildRecord`、`Level`、`LogRecord`、`Sink`
- Produces: `Logger`（`debug/info/warn/error/child/addSink/removeSink/setLevel/flush/dispose/stats`）、`createLogger(options?: { level?: Level; name?: string; sinks?: Sink[]; now?: () => number; flushIntervalMs?: number; maxBuffer?: number; stackLevel?: Level | "off"; batch?: boolean }): Logger`、`RingSink = Sink & { read(count?: number): LogRecord[] }`、`createRingSink(size: number): RingSink`、`hasStdout(): boolean`

- [ ] **Step 1: 写失败测试**

`test/unit/logger.test.ts`（默认参数：`flushIntervalMs: 0` 关定时器，全部手动 `flush()`，保证确定性）：

1. `createLogger({ now: () => 42, sinks: [s] })` 后 `info("x")` 时 sink **未**被调用；`logger.flush()` 后 sink 收到 `[{ time: 42, level: "info", msg: "x" }]`。
2. 连写 1000 条 `info` 后 `flush()`，sink 只被调用 1 次，批次长度 1000，顺序与写入一致。
3. `warn` 立即刷：`info`→`info`→`warn` 之后（未手动 flush）sink 已被调用 2 次，第一批 2 条、第二批 1 条。
4. `error` 同理：`info`→`error` 之后 sink 被调用 2 次。
5. `createLogger({ level: "warn" })` 时 `info` 不进缓冲，`flush()` 后 sink 不被调用。
6. `setLevel("debug")` 之后 `debug` 能进缓冲。
7. 两个 sink 收到同一个 batch 数组（引用相同）。
8. 第一个 sink 抛错时 `flush()` 不抛，第二个 sink 仍收到该 batch。
9. `child({ name: "db", traceId: "t1" })` 后 `child.info("x")` + flush → 记录含 `name: "db"` 与 `traceId: "t1"`；父 logger 的记录不含 `traceId`。
10. `addSink` 后新 sink 收到后续 batch；`removeSink` 后不再收到。
11. 子 logger 自己 `addSink(s)` 后，子的记录进 `s`，父的记录不进 `s`（子成立时快照父的 sink 列表）。
12. 缓冲上限：`maxBuffer: 3` 写 10 条后 `flush()`，sink 收到 3 条（最后三条），`logger.stats().dropped === 7`。
13. 栈：默认 `stackLevel: "warn"` 时 `warn` 记录的 `stack` 是字符串且包含测试文件名，`info` 记录没有 `stack`；`stackLevel: "off"` 时 `warn` 也没有。
14. `dispose()` 会把缓冲区里剩余的记录写出去，之后 `info()` 不抛不再调度；`dispose()` 之后 `stats().dropped` 不变。

`test/unit/ring.test.ts`：

1. `createRingSink(3)` 写 5 条（一个 batch）后 `read()` 返回最后 3 条，旧在前。
2. `read(2)` 返回最后 2 条。
3. 往容量 3 的 ring 写 10000 条（多个 batch）不抛，`read().length === 3`。
4. ring 能作为 sink 被 `logger.addSink` 收下，`flush()` 后读到记录。

- [ ] **Step 2: 跑测试确认失败**

Run: `bun test test/unit/logger.test.ts test/unit/ring.test.ts`

- [ ] **Step 3: 实现**

`createLogger` 返回对象字面量（不用 class），内部持：`level`、`name`、固定字段、`sinks` 数组、`buffer` 数组、`dropped` 计数、`timer` 句柄、`timerScheduled` 布尔。

`src/core/runtime.ts` 只放一个函数：`hasStdout()` 返回 `typeof process !== "undefined" && typeof process.stdout?.write === "function"`。logger 的 `batch` 默认值与 stdout sink 的写入选择都用它，避免两处各写一遍探测逻辑。

`emit(level, args)` 四步：按 `LEVELS` 过滤 → `stackLevel` 命中时采集调用栈（`new Error().stack`，按行剔除掉 logger 自身的帧）→ `buildRecord` → 入缓冲。当 `LEVELS[level] >= LEVELS.warn` 时立即 `flush()`；否则如果 `buffer.length >= maxBuffer`（默认 10000）就丢最旧的并 `dropped++`。`flushIntervalMs` 默认 100。

`flush()` 把 `buffer` 整体换出（`const out = buffer; buffer = []`），然后遍历 sinks 调一次 `sink(out)`，每个包 `try/catch`，首次失败 `console.error` 一行（闭包布尔量）。空的 buffer 不调 sink。

定时刷新：`batch` 为真且 `flushIntervalMs > 0` 时，入缓冲后如果没排上定时器就 `setTimeout(flush, flushIntervalMs)`，回调里置 `timerScheduled = false`。`batch` 默认值就是 `hasStdout()`——Workers 上为假，于是每条日志立即 flush。

`child` 返回新 logger：共享父的 buffer 与 sinks 快照（新增的 sink 只进自己的列表）、固定字段合并。
`stats()` 返回 `{ dropped }`。`dispose()`：`clearTimeout`、`flush()`、把每个 sink 上可选的 `close?.()` 调一次。
`ring.ts` 用定长数组 + 写指针；`sink(batch)` 逐条写入，满则覆盖最旧。

### Task 4: 鉴权

**Files:**
- Create: `src/console/auth.ts`、`src/console/types.ts`
- Test: `test/unit/auth.test.ts`

**Interfaces:**
- Produces: `AuthOptions { users: Record<string, string>; secret?: string; ttlMs?: number }`（`ttlMs` 默认 12 小时）、`Auth { login(user: string, password: string): Promise<string | null>; verify(token: string | null): Promise<{ sub: string } | null> }`、`createAuth(options: AuthOptions & { now?: () => number }): Auth`

- [ ] **Step 1: 写失败测试**

1. 正确密码 → token 非空；`verify(token)` 得到 `{ sub: "admin" }`。
2. 错误密码 → `null`。
3. 不存在的用户 → `null`。
4. 过期：注入 `now`，推进超过 `ttlMs` 后 `verify` → `null`。
5. 篡改：改 payload 段一个字符后 `verify` → `null`。
6. 垃圾输入：`verify("")`、`verify("a.b")`、`verify("!!!")`、`verify(null)` 都返回 `null` 且不抛。
7. 换 secret 签的 token 验不过。
8. 不传 secret 时 `createAuth` 不抛，`login` 仍可用。

- [ ] **Step 2: 跑测试确认失败**

Run: `bun test test/unit/auth.test.ts`

- [ ] **Step 3: 实现**

`login` 用等时比较密码（两边编码成 `Uint8Array`，长度不等直接 `null`，否则逐字节 XOR 累加后判零）。成功后 `crypto.subtle.importKey("raw", secret, { name: "HMAC", hash: "SHA-256" }, false, ["sign"])` 签 `base64url(JSON.stringify({ sub, exp }))`，token = `payload + "." + base64url(sig)`。
`verify` 按 `.` 切两段，段数不对直接 `null`；重算签名并等时比较；最后校验 `exp > now()`。
secret 缺省时用 `crypto.getRandomValues(new Uint8Array(32))`，并在创建时 `console.warn` 一行。


1. 公开命令 + 无 token → 200，`{ ok: true, output }`。
2. 受限命令 + 无 token → 401，body `{ ok: false, error: "unauthorized" }`。
3. 受限命令 + 合法 token → 200。
4. 未知命令 → 200，`error === "unknown command: foo"`。
5. 命令抛 `CommandError("boom")` → 200，`error === "boom"`。
6. 命令抛普通 `Error("secret detail")` → 200，`error` 只含 `message`，不含 `stack`。
7. 非 JSON body → 400。
8. body 超过 `maxBodyBytes` → 413。
9. `line` 不是字符串 → 400。
10. 命令返回永不 resolve 的 Promise + `timeoutMs: 10` → `{ ok: false, error: "timeout" }`，不抛。

- [ ] **Step 2: 跑测试确认失败**

Run: `bun test test/unit/exec.test.ts`

- [ ] **Step 3: 实现**

先读 `req.text()` 并按 `TextEncoder` 字节数比对 `maxBodyBytes`（默认 4096）→ 413；`JSON.parse` 失败 → 400；`line` 非字符串 → 400；`splitArgs` 取首段找命令（找不到 → 200 + `unknown command: <name>`）。鉴权：`command.public` 为真跳过，否则 `await auth.verify(req.headers.get("authorization")?.replace(/^Bearer /, ""))`，null → 401。执行用 `Promise.race` 对 `timeoutMs`（默认 10000）超时，用一个内部哨兵变量区分超时与业务抛错；**`finally` 里必须 `clearTimeout`**，否则每个请求都留一个 10 秒定时器，进程退不掉、测试也会拖尾。所有响应 `Content-Type: application/json; charset=utf-8`。
